# Embedded Agent Skills

Three focused engineering skills, with deterministic upstream GitHub monitoring and draft PR generation. Designed for MCU, bare-metal, RTOS, embedded Linux and heterogeneous SoC work without mandatory cross-loading of unrelated instructions.

| Skill | Activate for | Core boundary |
| --- | --- | --- |
| [`embedded-architect`](skills/embedded-architect/) | Computing model, system partitioning, timing/power budgets, interfaces, boot/recovery, architecture trade-offs | Makes/justifies architecture decisions; does not need to author every driver |
| [`embedded-developer`](skills/embedded-developer/) | Implementing/reviewing MCU C/C++, ISR, DMA, RTOS, peripheral, BSP or low-level Linux code | Minimal code changes and target build; delegates independent verification |
| [`embedded-qa`](skills/embedded-qa/) | Unit/host tests, static checks, Renode/Robot Framework, J-Link/ST-Link, HIL and real-board tests | Distinguishes simulated behavior from physical measurements |

Skill metadata is short; the body of each `SKILL.md` loads after skill selection. Detailed references are conditional. No fourth "skill-updater" skill runs in normal coding conversations.

## Quick start: publish as a GitHub repository

1. Extract the **repository ZIP** so `skills/`, `maintenance/`, `scripts/`, `tests/` and `.github/workflows/` are at repository root.
2. Create a GitHub repository (suggested: `embedded-agent-skills`) and push the extracted files to its default branch (`main` recommended). **This archive does not create a remote repository.**
3. In repository Settings > Actions > General, allow GitHub Actions to create and approve pull requests (organization admins may need to allow it). The upstream workflow explicitly requests `contents: write` and `pull-requests: write` for its `GITHUB_TOKEN`.
4. Run **Actions > Check primary embedded sources > Run workflow** to confirm access and review logs. It also runs on Mondays at 08:23 UTC (GitHub schedule timing is approximate, not guaranteed).
5. If upstream changes are detected, it creates or refreshes a **draft PR** on `automation/upstream-source-review`. Review the links and classify each change **adopt/reject/defer** before merging. **No LLM inference/API key is involved.**

### Example initialization in PowerShell

```powershell
# Run from the extracted repository root; create an empty GitHub repo first.
git init -b main
git add .
git commit -m "Initial embedded skills and upstream monitoring"
git remote add origin https://github.com/<OWNER>/embedded-agent-skills.git
git push -u origin main
```

## Install the skills into an agent

The repository is the source of truth. Use each skill's folder as an independently installable skill. Choose the location supported by the tool (e.g. `.claude/skills/`, `.agents/skills/`, or `.codex/skills/`). On platforms that only accept one skill ZIP per install, use `dist/<name>/skill.zip`, generated by:

```bash
python scripts/package_all.py
```

`embedded-architect` is intended for substantive design or architecture reviews. `embedded-developer` is the default for code changes. If migrating, uninstall older identifiers (`embedded-architecture`, `embedded-firmware`, `embedded-firmware-developer`) to avoid duplicate activation. This version renames the skills but retains the existing development and QA workflows. `embedded-qa` is the test/verification capability; all three need not be loaded for small tasks. Installation/auto-discovery varies by agent platform.

## Automated upstream PRs: Option A (no LLM)

The curated monitor list is in [`maintenance/sources.json`](maintenance/sources.json), with the last accepted source revisions in [`maintenance/reviewed-revisions.json`](maintenance/reviewed-revisions.json). As of **2026-10-18**, 16 monitors include source skills (Jeffallan, Rovinax, ESP32 specialist skills, MCU board profiles, build/debug tooling, Renode-specific TMNL references and Agile-V evidence guidance) and official STM32C0, Torizon, Renode, ESP-IDF, FreeRTOS and Zephyr repositories.

- **Files mode:** Inspect HEAD SHA of a pinned branch; only create a PR when changes touch watched paths. GitHub Compare API data is used; incomplete comparisons fail safe by creating a manual-review PR instead of silently ignoring risk.
- **Release mode:** Inspect the newest *stable GitHub release*, not every development commit or prerelease. A newly published stable Renode/ESP-IDF/FreeRTOS/Zephyr release creates a PR. Actual project upgrade is never implied.
- **No relevant change:** No report/PR. Unrelated upstream commits are deliberately not checkpointed on the default branch; a later run may compare the same range again (small, token-free API cost).
- **Relevant change:** Update a Markdown review report and propose advanced baselines **only inside the draft PR**. Changes to actual skills require human review and a separate patch or an explicitly reviewed addition to that PR.
- **Upstream failures:** API failures abort rather than masquerade as "no change". GitHub's Compare API has limits; comparisons above the conservative threshold become manual-review proposals.

See [`maintenance/UPSTREAM_POLICY.md`](maintenance/UPSTREAM_POLICY.md) for exact limits and governance. To add a source, add a monitor and **verified** SHA/tag to both JSON files, and run tests. Avoid copying arbitrary new upstream instructions into active skill folders.

### GitHub Actions included

- `.github/workflows/upstream-review.yml`: Scheduled / manually dispatched source detection and draft PR creation. Third-party actions pinned to specific commit SHAs.
- `.github/workflows/validate-skills.yml`: On push, PR, or manual dispatch, validate metadata/links, source manifests, the detector test suite, and the Robot XML summarizer test suite.

**Important GitHub behavior:** Pull requests created with `GITHUB_TOKEN` do not automatically trigger other `push`/`pull_request` workflows. Accordingly, the upstream workflow itself runs validation before creating/updating a PR. Additional merge protection may require moving the draft PR to ready-for-review to trigger subsequent checks, or using an appropriately scoped GitHub App token. Do not assume an auto-generated PR received independent CI checks.

## Local verification

```bash
python scripts/validate_skills.py
python -m unittest discover -s tests -v
python -m unittest discover -s skills/embedded-qa/tests -v
python scripts/check_upstream.py --dry-run  # requires internet; GH_TOKEN recommended
python scripts/package_all.py
```

The QA skill cannot claim that Renode models the exact chip, or that physical power/timing is verified, without on-target evidence.

## Security / ownership

- **Upstream repositories are untrusted inputs.** The detection workflow reads only GitHub metadata, changed paths and release tags; it does not clone, import or run third-party scripts.
- This repository currently contains original/curated instructional text. It does not bundle external code assets or imply compliance with an external safety/coding standard.
- Review all upstream changes against official vendor documentation and the actual target SDK/version. Versioned release tags do not automatically justify project upgrades.
- No repository license is imposed in this package. Decide and add the appropriate license before public distribution.
