# ESP32 / ESP-IDF target checks

Load only for ESP32-family projects. Verify exact SoC (ESP32, S2, S3, C3, C6, H2, etc.), module/board variant, silicon revision, `IDF_TARGET`, ESP-IDF release and `sdkconfig`; capabilities and pin numbers vary materially.

1. **GPIO and boot:** Verify the exact SoC's strapping pins, flash/PSRAM pins, USB-JTAG/UART bootloader usage, output-capable vs input-only pins, voltage/current, and external pulls at reset. Classic ESP32 pin lists do *not* apply to ESP32-S3/C3/C6.
2. **RTOS:** Inspect ESP-IDF FreeRTOS flavor and core count. Pin tasks only for demonstrated peripheral, timing, locality, or concurrency needs; unpinned affinity may be valid. Verify per-version task stack units: ESP-IDF's task-creation APIs specify stack depth in **bytes**, unlike common vanilla FreeRTOS ports, whose stack depth is in words. Verify actual headers/docs for the installed release.
3. **Interrupts and cache:** Use IRAM-safe interrupt registration only when required for operation while flash cache is disabled/for latency. `IRAM_ATTR` alone is insufficient: the whole call graph plus constant and mutable data must be in IRAM/internal DRAM. Do not add `ESP_INTR_FLAG_IRAM` blindly. Check API use and synchronization rules of the installed IDF port.
4. **Memory / DMA:** Check `heap_caps` requirements (e.g. DMA-capable and internal memory), PSRAM accessibility, cache-disabled windows, alignment, stack location, radio coexistence, and bootloader/flash constraints. Do not assume all buffers may live in PSRAM.
5. **Lifecycle:** For OTA/NVS/security changes inspect actual partition CSV, bootloader, rollback enablement and self-test flow; check reset and power-cut behavior. eFuses, secure boot, flash encryption, and anti-rollback can be irreversible: require explicit approval and recovery planning before writing.
6. **Evidence:** Use `idf.py build` and project tests for compilation, but flash/monitor/integration/power readings are distinct hardware qualifications and must not be reported as passed without actual runs.

Versioned primary docs to check for the *actual target*: [ESP-IDF FreeRTOS](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/freertos_idf.html), [interrupt allocation](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/intr_alloc.html), [GPIO](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/gpio.html), [OTA](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/ota.html). The links use the original ESP32 as an example only; choose the correct SoC's documentation before use.
